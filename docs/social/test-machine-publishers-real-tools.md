## LinkedIn

A machine publisher can look least-privileged on paper and still fail when a repository or media policy checks a capability you missed.

The stronger contract boots the application and exercises the registered tools: create a draft, verify anonymous denial, publish, retract, and upload an image. It also proves the principal cannot administer content or create unrelated bundles.

I wrote up why mandatory authorization wiring, narrow protected-read policies, and claims invalidation belong in the same acceptance test: https://jonesrussell.github.io/blog/test-machine-publishers-real-tools/

## Facebook

Do not test a machine publisher by reviewing its permission list alone.

Run the real registered tools. Prove it can create, publish, retract, and upload what it owns. In the same test, prove it cannot administer all content, create unrelated bundles, or act for an anonymous caller.

That is how least privilege becomes an executable contract: https://jonesrussell.github.io/blog/test-machine-publishers-real-tools/
